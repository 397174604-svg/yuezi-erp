# P0 财务合同分支验收（2026-07-31）

## 1. 本轮范围与结论

依据 `月子会所功能开发清单-按端拆分-128项-2026.xlsx` 的「ERP后台（Web）」页，核查 F007～F016、F020。表格中的状态均写为“✅已建成”，但本轮按代码、路由、API 和数据源重新核验后，**不能把表格状态直接当成上线验收结论**。

当前仓库同时存在两套后台：

1. `src/ + server/mvp_api.py`：当前 Vue2 ERP，具备 MySQL 业务接口，是本轮实际修复和可交付主线。
2. `apps/admin`：Vue3 管理端，页面覆盖 F007～F016、F020，但 `dataKind()` 将这些页面标为 `demo`，调用的 `/api/v1/*` 财务接口在本仓库内没有服务端实现，不能作为生产闭环。

本轮已修复最容易造成串店和错账的阻断项：收款、退款、合同写入不再隐式使用默认门店；必须先选择具体门店。全部门店仅可查询，不允许新建无归属单据。新增的 P0 主链防错还包括：中心店允许暂不选择套餐保存合同；黄河路店必须选择本店当前有效、已发布的套餐价格；合同至少存在一笔已审核收款后才能订房。

## 3. 本轮代码修复

### 3.1 具体门店写入闸门

- `server/mvp_api.py` 的 `_finance_store_id()` 和 `_sales_store_id()` 不再回退 `default_store_id` 或账号唯一门店。
- 未传门店或传“全部”时，API 直接拒绝写入，提示“全部门店仅用于查询”。
- 合同表单和收款/退款表单把门店移到客户、收款人等下游字段之前。
- 切换门店时清空已选客户、收款人及其隐藏 ID，防止把上一门店实体带入新单据。

### 3.2 门店范围内选择客户和收款人

- 财务选择器 API 新增 `store` 参数，打开客户/员工选择器前必须先选具体门店。
- 收款人严格来自发生门店。
- 普通客户只在所属门店办理；已有 `customer_accounts` 会员账户的客户允许跨店办理。
- 无论会员是否跨店，收款/退款/合同仍写入本次业务发生门店，便于分店核算。

### 3.3 第二套管理端防误写

- `apps/admin` 合同页在 `auth.storeId` 为空（全部门店查询视角）时禁用新建、编辑、收款、审批、删除。
- 新建合同明确提交 `storeId`。
- 注意：该管理端财务页仍被仓库标记为 `demo`，且其 `/api/v1` 服务端不在本仓库，不能因 UI 可点击而标记为上线完成。

### 3.4 合同套餐和订房顺序防错

- 中心店合同没有选择套餐 ID 时可继续保存，保留现阶段线下确认套餐的业务空间。
- 黄河路店合同未选择套餐时返回 HTTP 400、业务码 `40000`，提示“黄河路店合同必须选择本店已发布套餐”。
- 选择套餐后，后端仍会按门店、房型、入住天数、签订日期和发布状态再次校验，前端传入的手工参考价不能覆盖已发布价格。
- 已审核合同在 `paid=0` 时创建订房返回 HTTP 400、业务码 `40000`，提示“合同至少有一笔已审核收款后才可订房”。只有收款审批更新合同实收后才能继续订房。
- 真实 MySQL 验收脚本会从黄河路店的正式套餐主数据中选择一条有效价格规则，不写入伪造套餐；测试结束会按外键顺序清理合同套餐快照、权益、收款、订房和客户。

## 4. 操作验收路径

### 收款

1. 左侧进入「财务管理 → 新增收款」。
2. 先选“收款分店”。
3. 点击“收款人”和“选择客户”，确认列表只显示该门店员工，以及该门店客户/可跨店会员。
4. 填写款项类别、结算方式、金额、银行和日期后保存。
5. 进入「财务管理 → 收款管理」，按门店查询，审核后检查实收、到账、审计轨迹。

### 退款与报销

1. 进入「财务管理 → 退款申请」，先选退款分店，再选客户。
2. 保存、提交后进入「退款审核」执行审核；打款必须填写实退金额和方式。
3. 报销从「我的费用」新增，在「费用审核」审核，之后执行打款。

### 发票

1. 在「收款管理」选择已审核记录，执行开具发票。
2. 在「财务管理 → 发票管理」查询、导出并核对发票抬头、税号、金额和开票时间。

### 合同

1. 进入「销售管理 → 合同管理」。
2. 新建时先选签单门店，再选择/填写客户和套餐。
3. 保存草稿或提交审核；审核后到收款页按相同业务门店登记收款。
4. 用普通跨店客户测试时应被拒绝；有会员账户的客户可跨店，但合同和流水归本次签单门店。
5. 中心店不选套餐应可保存；黄河路店不选套餐应显示明确提示，选项必须来自黄河路店已发布套餐。
6. 审核合同后直接订房应被阻止；完成一笔收款并审核后才允许订房。

## 6. 404、死按钮和持久化审计

- Vue2 财务和合同 API 路径由 `server/mvp_api.py` 提供，未发现本轮入口直接指向不存在的 Vue2 路由。
- “星支付”“扫码支付”没有真实支付通道，当前按钮只提示并阻止生成假支付结果，这是安全降级，不是完成状态。
- Vue3 `apps/admin` 的财务页面调用 `/api/v1/contracts`、`/api/v1/recharges`、`/api/v1/approval`、`/api/v1/refunds`、`/api/v1/invoices`、`/api/v1/reconcile`、`/api/v1/cost`、`/api/v1/reports/recharge` 等；本仓库只找到客户端声明，未找到对应服务端路由，单独启动时可能出现 404/连接失败。
- Vue2 主线写入 MySQL 表，不以页面 Mock 数组作为财务真账；但本机缺少数据库凭据和 PyMySQL，本轮没有伪造“已持久化成功”的结论。
