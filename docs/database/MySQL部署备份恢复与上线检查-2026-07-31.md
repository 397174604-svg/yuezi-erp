# 奇德芬芳 ERP：MySQL 部署、备份恢复与上线检查

> 日期：2026-07-31
> 适用范围：Web ERP API、MySQL 5.7、两门店内部试运行
> 当前结论：仓库已具备可重复执行的迁移、安全配置校验、逻辑备份/恢复工具和部署样例；本次没有生产数据库、域名、证书或运维主机，因此不能据此声称已经上线。

## 1. 数据持久化边界

- 正式 API 只读取 MySQL，不回退 JSON/Mock。
- `database/mysql/reference/yuezi-legacy-schema-20260725.sql` 是 2026-07-25 的**结构基线**，不包含生产业务数据。
- `V001`～`V003` 是组织、员工和 RBAC 基线迁移；`V004` 起由常规运行时迁移管理。
- `schema_migrations` 保存版本、说明、SHA-256 和执行时间。服务会拒绝校验和变化、未知已执行版本及迁移序号断档。
- 迁移使用 MySQL `GET_LOCK` 防止两个发布进程并发执行。MySQL DDL 存在隐式提交，迁移失败时不能假定所有 DDL 自动回滚；发布前备份和演练库验证仍是强制步骤。
- `deploy/mysql/docker-compose.yml` 的命名卷只适合本地/测试或单机试运行。生产优先使用有磁盘快照、监控、主从/高可用和异地备份能力的受管 MySQL。

## 2. 新库初始化

新库初始化需要 DBA 权限，应用运行账号不得拥有 `CREATE USER`、`GRANT` 或全库管理权限。

1. DBA 创建 `utf8mb4` 数据库及迁移账号、应用账号、只读审计账号、备份账号。
2. 使用安全的 MySQL option file 导入结构基线：

   ```powershell
   mysql --defaults-extra-file=C:\secure\migration.cnf < database\mysql\reference\yuezi-legacy-schema-20260725.sql
   ```

3. 设置迁移账号环境变量后，首次且仅首次执行：

   ```powershell
   npm run migrate:mysql:baseline
   ```

4. 后续发布只执行：

   ```powershell
   npm run migrate:mvp
   ```

5. 组织员工数据只能从受控的 `.private/employee-import/` 来源导入。`reset-import` 会清空 `yuezi` 业务表，只允许在已备份、已确认的初始化/重建窗口执行，不能作为普通发布步骤。
6. 执行管理员初始化与代表账号初始化；密码只通过当前进程环境或密钥管理服务提供：

   ```powershell
   npm run bootstrap:mvp
   npm run bootstrap:mvp:roles
   ```

## 3. 最小权限数据库账号

建议拆分：

| 账号 | 用途 | 最小权限 |
| --- | --- | --- |
| `yuezi_migrator` | 发布窗口迁移 | 目标库 DDL + DML；仅发布时启用 |
| `yuezi_app` | API 运行 | 目标库业务表 `SELECT/INSERT/UPDATE/DELETE`，不授予用户和权限管理能力 |
| `yuezi_auditor` | 权限与完整性审计 | 目标库 `SELECT` + `information_schema` 必需读取 |
| `yuezi_backup` | `mysqldump` | 目标库 `SELECT/SHOW VIEW/TRIGGER/EVENT`，按实际客户端要求补最小锁权限 |

实际 `GRANT` 由 DBA 按服务器版本和备份参数审核后执行，不在仓库保存密码。

## 4. 全量逻辑备份

先检查客户端：

```powershell
npm run backup:mysql:check
```

创建压缩备份：

```powershell
$env:ERP_DB_USER='yuezi_backup'
$env:ERP_DB_PASSWORD='<由密钥服务注入>'
python scripts/mysql-backup.py backup `
  --output E:\ERP-Backups\yuezi-20260731-220000.sql.gz
```

工具使用 `--single-transaction --quick`，同时导出 schema、data、routines、events 和 triggers；备份完成后原子改名，并生成 `.manifest.json`，记录 SHA-256、大小和客户端版本。密码通过临时权限受限 option file 传给客户端，不出现在命令行。

校验：

```powershell
python scripts/mysql-backup.py verify `
  --backup E:\ERP-Backups\yuezi-20260731-220000.sql.gz
```

建议试运行最低策略：

- 每日 1 次全量逻辑备份，保留 35 天。
- 数据库/磁盘快照至少每日 1 次；若业务量允许，结合 binlog 将 RPO 收敛到 15 分钟以内。
- 至少一份备份复制到不同故障域并加密；备份目录禁止 Web/API 账号读取。
- 每月至少一次恢复演练，并记录备份 SHA-256、耗时、表数、核心行数和 RBAC 测试结果。

## 5. 受保护恢复

默认只允许恢复到 `yuezi_restore_*` 演练库，目标库需由 DBA 预先创建：

```powershell
python scripts/mysql-backup.py restore `
  --backup E:\ERP-Backups\yuezi-20260731-220000.sql.gz `
  --database yuezi_restore_20260731 `
  --confirm-database yuezi_restore_20260731
```

非演练库需要同时满足：

1. `--allow-non-scratch-target`；
2. `ERP_ALLOW_LIVE_RESTORE=YES:<目标库名>`；
3. 已完成停机、现库备份、审批和精确目标确认。

恢复后必须执行：

```powershell
npm run migrate:mvp
npm run verify:mvp
npm run audit:db:security
npm run test:mvp:rbac
```

再抽查租户/门店数、员工数、客户/合同/收款/订房数、`schema_migrations` 和审计事件。未完成这些检查不得切换 API。

## 6. RBAC 与跨店隔离

- 所有账号必须有有效角色和显式 `user_stores`；没有门店授权时查询返回空、写操作返回 `403`。
- `SYS_ADMIN` 也不能通过请求参数写入未授权门店；跨店能力通过给管理员显式授予两店实现。
- 登录态只接受与账号同租户的角色和门店；角色停用、授权过期或门店停用后下一次请求立即失效。
- 客户、合同、收款、订房和房间均使用 `tenant_id + store_id` 边界；客户—合同、合同—收款、合同—订房、业务员—客户还会校验门店一致。
- 员工手机号在通用组织/系统列表默认脱敏；客户手机号按 `field_permissions` 决定明文或脱敏。
- `role_data_scopes` 已返回给前端/审计层，但部门/本人范围要完全生效，仍需逐业务表确认责任人字段。当前上线口径只能声明“租户/门店级隔离已实现并待真实库验证”，不能声明所有 71 项功能均完成部门/本人隔离。

只读完整性审计：

```powershell
npm run audit:db:security
```

该命令发现跨租户员工绑定、默认门店、账号门店、账号角色、无门店账号、无角色账号和非法数据范围时返回非零退出码。

## 7. Mock、正式 API 与回退

| 模式 | 命令 | 数据源 | 用途 |
| --- | --- | --- | --- |
| 本地 Mock | `npm run dev` | `mock/erp-demo.js` | 无数据库的页面联调 |
| 本地真实 API | `npm run dev:mvp` | 本机 MySQL + API | 接口与业务验收 |
| 部署构建 | `npm run build:api` | `/api` 反向代理到 API | 内部试运行/生产候选 |

`.env.api` 和 `.env.mvp` 均显式关闭开发 Mock 注册。部署构建通过 Nginx 将 `/api/` 去前缀代理到 `127.0.0.1:3000`。回退时优先回退到上一个已验证的前端静态版本和 API 版本；本地 Mock 仅用于联调，禁止在正式域名作为生产数据替代品。

部署主机准备示例：

```bash
python3 -m venv /srv/yuezi-erp/venv
/srv/yuezi-erp/venv/bin/pip install -r server/requirements.txt
pnpm install --frozen-lockfile
pnpm run build:api
```

将 `dist/` 放到 Nginx 只读目录，将填写后的 API 环境文件放到 `/etc/yuezi-erp/api.env` 并限制为服务账号可读，再按 `deploy/systemd/` 和 `deploy/nginx/` 样例启用。真实路径、用户、证书和日志策略由运维调整。

## 10. 当前上线阻断项

- 当前 API 基于 Python `ThreadingHTTPServer`，可用于受控内网试运行，不宜直接暴露公网。正式生产前仍需补多进程/优雅停机、集中结构化日志、指标告警、统一限流和令牌撤销/轮换方案。
- 依赖安装输出已提示 Vue 2 结束维护、Axios 0.18.1 存在已知严重漏洞，另有多个旧依赖停止维护；本并行任务未直接升级前端技术栈，以免与 P0 业务主链冲突。公网开放或正式生产切换前必须安排独立依赖升级与回归。
- MySQL 5.7 是现有兼容基线；运维必须评估受支持数据库版本、升级路径和迁移兼容性，不能只依赖单机容器。
- 当前机器没有 MySQL 客户端、数据库凭据和生产基础设施，尚未完成真实迁移、全量备份、恢复、五类账号接口回归或故障切换演练。
