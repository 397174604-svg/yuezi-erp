# 原 ERP 权限迁移与优化说明

## 本次业务取舍

原系统采集到 36 个角色、69 条用户记录和 70 条用户角色关系。根据当前组织实际情况，不导入以下岗位：

- 面点师
- 勤杂工
- 企划
- 保安
- 司机
- 客房保洁
- 公共保洁
- 洗衣工

原始采集 CSV 作为证据保留在 `.private/system-settings-import`，没有删除或改写；目标 MySQL 仅导入过滤后的角色、账号与授权。

过滤结果：

| 项目 | 数量 |
| --- | ---: |
| 原角色 | 36 |
| 保留角色 | 28 |
| 排除角色 | 8 |
| 原用户记录 | 69 |
| 导入账号 | 64 |
| 启用账号 | 58 |
| 沿用禁用状态 | 6 |
| 因岗位排除而不导入的用户 | 5 |
| 保留用户角色关系 | 65 |
| 多角色账号 | 1 |

## 原系统权限实现方式

原系统采用“角色—菜单—按钮—数据部门”四层授权：

1. 用户通过 `userKeyId` 与一个或多个 `roleKeyId` 建立关系。
2. Web 后台菜单和 App 菜单分别维护授权，二者不是同一套菜单树。
3. 页面按钮作为菜单下的独立授权项，例如浏览、新增、编辑、删除、审核、打印。
4. 数据权限不是简单的全局部门范围，而是按“角色 + navId + 部门”逐页授权。
5. `admin` 是独立超级管理员；“ERP管理员”是普通角色，二者不能合并。
6. 原系统允许不同角色 ID 使用相同显示名称，例如角色 8 和角色 89 都叫“护士”。

本地证据规模：

| 权限证据 | 原始数量 | 本次保留导入 |
| --- | ---: | ---: |
| Web 权限目录 | 1,067 | 1,067 |
| Web 角色授权 | 12,826 | 12,464 |
| App 权限目录 | 198 | 198 |
| App 角色授权 | 957 | 405 |
| 按页面数据范围 | 3,538 | 3,538 |

App 授权减少较多，是因为被排除角色在原系统 App 端具有大量重复菜单授权。

## 新系统优化模型

### 稳定身份

- 角色以 `legacy_role_id` 和唯一角色编码标识，不再以中文名称作为唯一键。
- 用户以 `legacy_user_id` 标识，同时保留原登录名。
- 支持同名角色和一人多角色。
- 6 个原系统停用账号在新系统保持 `DISABLED`，不能登录。

### 权限资源统一

- 原 Web/App 菜单和按钮转换为统一的 `permissions` 资源。
- 原始菜单 ID、按钮 ID、名称和前端/App来源保存在 `legacy_permission_resources`。
- 后端与前端使用相同权限编码，例如：
  - `LEGACY.WEB.N{菜单ID}.B{按钮ID}`
  - `LEGACY.APP.N{菜单ID}.B{按钮ID}`
- Vue 的路由过滤支持 `meta.permissions` 和 `meta.legacyNavId`。
- `v-permission` 同时支持角色编码与权限编码。

### 数据范围分层

- `user_stores` 只表示员工所属门店，不再混入跨店授权。
- 原系统逐页部门范围保存在 `legacy_role_data_scope_grants`。
- 登录信息返回当前账号的逐导航数据范围。
- `SYS_ADMIN` 固定拥有两个门店；普通账号按员工或部门确定所属门店。
- 当前 MVP 业务接口继续采用保守的门店过滤；后续业务模块接入时再按对应 `navId` 叠加部门/本人范围。

### 密码与账号

原用户采集文件没有密码或密码哈希。本机新增账号使用临时密码 `000000`，并设置 `must_change_password=1`。现有已验证账号密码保持不变。

该临时密码方案仅用于本机验收。生产上线前必须完成：

- 一人一个随机临时密码；
- 首次登录强制修改密码；
- 管理员重置密码；
- 登录失败锁定和审计；
- 禁止共享默认密码。

## 已知待处理项

- 44 个账号已经关联现有员工花名册。
- 14 个启用账号属于功能账号、花名册缺失人员或姓名/部门无法唯一匹配，目前可登录但 `staff_id` 为空，需人工核对。
- 28 个保留角色中，当前启用账号实际覆盖 19 个角色名称；其余角色作为可分配角色保留。
- 已排除岗位不会出现在原角色导入结果中；现有本地“企划专员”占位角色已标记为 `RETIRED`。
- 非 MVP 模块仍需要逐页把原 `navId` 和按钮 ID 接到真实 API 授权中间件，不能只依赖前端隐藏。

## 可重复执行

```powershell
$env:ERP_DB_PASSWORD='<MySQL密码>'
$env:ERP_LEGACY_ACCOUNT_INITIAL_PASSWORD='<本机临时密码>'
npm run migrate:mvp
npm run import:legacy:access
npm run verify:legacy:access
```

测试全部保留账号：

```powershell
$env:ERP_BOOTSTRAP_ADMIN_PASSWORD='<管理员密码>'
$env:ERP_SALES_ACCOUNT_PASSWORD='<销售账号密码>'
$env:ERP_RECOVERY_ACCOUNT_PASSWORD='<产康账号密码>'
$env:ERP_ROOM_ACCOUNT_PASSWORD='<客房账号密码>'
npm run test:legacy:accounts
```

导入脚本是幂等的。重复运行会更新角色、权限和账号关系，不会复制业务数据。
