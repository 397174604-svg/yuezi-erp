# 奇德芬芳 ERP 最小可用 MVP

## 当前结论

现有项目此前主要完成了旧 ERP 页面字段复刻，业务接口仍由 Mock 返回临时编号和空列表。数据库已有组织、员工、角色和权限结构，但没有登录账号，也没有可运行的客户业务数据。

本次将首个可用版本收敛为：

`客户建档 → 合同签订/审核 → 收款登记/审核 → 订房 → 入住`

该链路已经接入本机 MySQL 5.7，所有业务动作通过事务落库，不再使用 JSON 或 Mock 数据。

## 已完成

### 登录与权限边界

- MySQL `user_accounts` 真实账号登录。
- PBKDF2-SHA256 密码哈希。
- 12 小时签名令牌。
- 用户—角色、用户—门店关系读取。
- 客户、合同、收款、订房和入住动作均按权限编码进行服务端校验。
- 前端菜单、业务表单和操作按钮按同一组权限编码显示。
- 已导入过滤后的 28 个原系统角色和 64 个账号；管理员、销售经理、产康师和客房管家的 MVP 主链路权限已完成端到端验证。
- 所有业务查询均按当前账号的门店范围过滤。
- 客户手机号根据字段权限决定显示明文或脱敏值。

当前 MVP 权限矩阵依据原系统角色授权记录收敛如下：

| 角色 | 客户 | 合同 | 收款 | 订房/入住 | 数据范围 |
| --- | --- | --- | --- | --- | --- |
| 系统管理员 | 全部 | 新增、查看、审核 | 新增、查看、审核 | 订房、入住 | 两个门店 |
| 销售经理 | 新增、查看 | 新增、查看、审核 | 新增、查看、审核 | 订房、入住 | 所属门店 |
| 产康师 | 新增、查看 | 新增、查看，不可审核 | 新增、查看，不可审核 | 仅查看 | 所属门店 |
| 客房管家 | 新增、查看 | 不可进入 | 查看、审核，不可新增 | 订房、入住 | 所属门店 |

账号使用原系统用户名和用户提供的原密码。产康原账号“许曼”在现有员工花名册中匹配到“许曼曼”，该身份映射后续仍需人工确认。

### 客户

- 客户姓名、手机号、微信号、门店、业务员、客户状态、来源、预产期和备注入库。
- 同租户手机号重复校验。
- 自动生成客户编号。
- 客户状态随合同、订房和入住自动流转。

### 合同

- 六种已核验合同类型：
  - 月子合同
  - 婴儿托管
  - 试住合同
  - 续住合同
  - 小月子合同
  - 到家合同
- 参考价格、成交金额、折扣率、套餐、入住天数、预住日期入库。
- 折扣率按 `成交金额 / 参考价格` 计算。
- 合同新增后进入“已签合同但未审核”，审核后进入“已审核”。
- 合同列表实时计算已入账、未入账和欠款。

### 收款

- 九种已核验收款类型。
- 收款金额、支付方式、收款时间、收款人和备注入库。
- 新收款进入“待审核”。
- 审核时锁定收款单和合同，避免重复入账。
- 审核后事务更新合同已收款。
- 已审核金额、未审核金额与本次金额不能超过合同成交金额。

### 客房

- 按门店读取房间。
- 已审核合同才能订房。
- 订房时校验同一房间的日期冲突。
- 订房后客户状态变为“已订房”，房态变为“已预订”。
- 入住后客户状态、订房状态和房态在同一事务中更新。

### 审计

- 客户、合同、收款和订房的新增、审核、入住动作写入 `mvp_audit_events`。
- 记录操作人、门店、业务对象、前后状态和必要业务摘要。

## 本地运行

不要把数据库密码或管理员密码写入项目文件。在 PowerShell 当前会话中设置：

```powershell
$env:ERP_DB_PASSWORD='<本机 MySQL 密码>'
$env:ERP_BOOTSTRAP_ADMIN_PASSWORD='<管理员登录密码>'
$env:ERP_TOKEN_SECRET='<至少 32 位随机字符串>'
npm run dev:mvp
```

前端地址：`http://localhost:9527/`

API 地址：`http://127.0.0.1:3000/`

首次在新数据库部署时执行：

```powershell
npm run migrate:mvp
npm run bootstrap:mvp
npm run bootstrap:mvp:roles
```

非管理员账号密码通过环境变量提供，不写入仓库：

```powershell
$env:ERP_SALES_ACCOUNT_PASSWORD='<销售账号密码>'
$env:ERP_RECOVERY_ACCOUNT_PASSWORD='<产康账号密码>'
$env:ERP_ROOM_ACCOUNT_PASSWORD='<客房账号密码>'
```

检查数据库状态：

```powershell
npm run verify:mvp
```

执行四类账号的只读权限回归：

```powershell
$env:ERP_SALES_ACCOUNT_PASSWORD='<销售账号密码>'
$env:ERP_RECOVERY_ACCOUNT_PASSWORD='<产康账号密码>'
$env:ERP_ROOM_ACCOUNT_PASSWORD='<客房账号密码>'
npm run test:mvp:rbac
```

该测试验证登录、角色编码、门店范围、模块读取权限及越权操作 `403`，不会创建业务记录。

执行一条自动清理的完整业务验收：

```powershell
python scripts/smoke-mvp.py
```

完整验收依次执行客户建档、合同新增/审核、收款登记/审核、订房和入住，成功后删除本次生成的客户、合同、收款、订房及审计数据，并恢复原房态。
